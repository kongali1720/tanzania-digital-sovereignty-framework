# Contributing Guidelines

Thank you for your interest in contributing to the Tanzania Digital Sovereignty Framework.

Contributions may include policy research, technical architecture, documentation,
cybersecurity recommendations, digital public infrastructure analysis, and
Indonesia–Tanzania collaboration proposals.

## 1. Before Contributing

- Read the project README and relevant documentation.
- Check existing issues and pull requests before starting duplicate work.
- For substantial changes, open an issue to discuss the proposal first.
- Do not submit confidential, classified, personal, or otherwise restricted information.

## 2. Contribution Process

1. Fork the repository.
2. Create a focused branch from `main`.
3. Make your changes.
4. Review spelling, links, formatting, and technical accuracy.
5. Submit a pull request describing the purpose and impact of your changes.

Suggested branch names:

- `docs/description`
- `feature/description`
- `research/description`
- `security/description`
- `fix/description`

## 3. Documentation Standards

- Use clear, professional English.
- Use Markdown headings consistently.
- Cite authoritative sources for factual and policy claims.
- Distinguish verified facts, proposals, assumptions, and recommendations.
- Include dates and source links where relevant.
- Avoid presenting proposed partnerships or capabilities as confirmed.

## 4. Security and Privacy

Never commit passwords, API keys, access tokens, private keys, personal data,
or confidential government or organizational information.

Report security vulnerabilities privately according to [SECURITY.md](SECURITY.md).

## 5. Pull Request Requirements

A pull request should:

- Explain what changed and why.
- Identify affected sections or files.
- Include references for new factual claims.
- Disclose known limitations.
- Avoid unrelated changes.

## 6. Review

Contributions may be reviewed for accuracy, clarity, relevance, security,
maintainability, and alignment with the project's objectives.

Submitting a contribution does not guarantee acceptance.

## 7. License

By submitting a contribution, you agree that it may be distributed under
the project's [MIT License](LICENSE), provided you have the right to contribute
that material.

Thank you for helping improve this project.
